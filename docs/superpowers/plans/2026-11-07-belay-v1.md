# Belay v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first release of Belay: a Claude Code plugin with a tested safety helper, a GitHub adapter, and three skills (`issue-create`, `pr-review`, `dispatch`).

**Architecture:** Markdown skills in the Agent Skills format sit on top of one standard-library Python helper (`scripts/belay.py`) that mechanically enforces the stop switch, time budget, attempt caps, evidence gating, high-risk paths and owner-only overrides. Skills talk to the tracker only through adapter documents (`shared/adapters/`). A repo validator and a cross-platform CI workflow keep every skill and the manifest honest.

**Tech Stack:** Python 3.11+ (standard library only: `argparse`, `tomllib`, `json`, `unittest`), the `gh` CLI, Markdown with YAML frontmatter, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-07-belay-design.md` (read it first; this plan argues from it).

**Out of scope for this plan:** the Jira adapter (needs a Jira site to test; separate plan), and the later skills `issue-ready`, `review-respond`, `status`.

## Global Constraints

- License MIT; public repo `github.com/bharatmane/belay`; nothing personal, secret, or company-specific may be committed; third-party material only per spec section 13.
- Helper: Python 3.11+ standard library only, a single file `scripts/belay.py`; no bash dependency; works on Windows, macOS, Linux.
- Config file: `.belay.toml` (spec section 8). Defaults: `active_minutes = 90`, `attempts_per_stage = 3`, `idle_minutes = 60`, labels `belay:ready|working|waiting|review|failed|stop|approved`.
- Plugin name `belay`; skills `issue-create`, `pr-review`, `dispatch`; skill `name` lowercase hyphens, at most 64 characters; `description` at most 1024 characters, aim under 500, starts with "Use when" or "Use only when", never summarises the workflow.
- `SKILL.md` bodies under 500 lines; heavy detail in `references/`.
- Belay never merges, approves, force-pushes, or resets published history; comments carry counts and ids only.
- Owner-resolved open question 2 (my call): PRs open as **draft** by default, config key `pr_draft = true`.
- Commit steps are **local commits only**. Never push, tag, or create GitHub resources without the owner asking.
- Exit codes (helper): 0 ok; 2 config, usage or corrupt state; 3 stop switch set; 4 budget or attempts spent; 5 another run is working; 6 run not found or illegal transition; 7 evidence missing for HEAD; 8 high-risk path without approval; 9 not the owner. Stdout is always one JSON object: `{"ok": true, ...}` or `{"ok": false, "code": N, "reason": "..."}`.

## Review Focus

1. A run record half-written by a crash must not crash the helper or lose the run (Task 3).
2. Two terminals claiming at once: exactly one wins (Task 3).
3. System sleep or a clock that jumps forward or backwards must not inflate or corrupt the active-time budget (Task 4).
4. `done`/`hand-off` after a new commit, or after evidence for a different command, must be refused (Task 5).
5. High-risk globs must match Windows-style paths and nested directories (Task 5).

### Task 3: Helper: run store, claim, stop switch, stale recovery

**Files:**
- Modify: `scripts/belay.py`
- Test: `tests/test_store.py`

**Interfaces:**
- Consumes: `Config`, `BelayRefusal`, `make_run_id` (Task 2).
- Produces:
  - `class RunStore` with `__init__(self, root: Path)`, `create(self, issue: str, tracker: str, now: datetime) -> dict`, `load(self, run_id: str) -> dict`, `save(self, run: dict) -> None`, `list_runs(self) -> list[dict]`, `lock(self) -> ContextManager[None]`.   - Run record keys: `run_id, issue, tracker, state ("working"|"waiting"|"review"|"failed"|"stopped"), stage, started_at, heartbeat, last_tick, active_seconds, attempts (dict), evidence (list), history (list), overrides (list), extension_minutes`. Timestamps are ISO-8601 UTC strings.
  - `check_stop(root: Path, cfg: Config, labels: Sequence[str] = ()) -> None` (raises code 3 if `<root>/.belay/STOP` exists or `cfg.labels["stop"]` is in `labels`)
  - `claim(store: RunStore, cfg: Config, issue: str, now: datetime, labels: Sequence[str] = ()) -> dict`: only a `working` run blocks a new claim (code 5); a `working` run whose heartbeat is older than `cfg.idle_minutes` is stale: same issue resumes it unchanged, a different issue marks it `failed` with history note `stale` and proceeds.
